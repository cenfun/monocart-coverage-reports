# 采集 V8 覆盖率 {#v8-collection}

## 第一步：构建准备 {#build}

如果源码需要经过编译或打包，请先开启构建工具的 sourcemap 支持，以便将运行时代码的覆盖率映射回源码。建议关闭压缩和 tree shaking，便于排查覆盖率问题，并保留需要统计的代码。

- [webpack](https://webpack.js.org/configuration/)：`devtool: 'source-map'`、`mode: 'development'`，参见 [webpack.config-v8.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/build/webpack.config-v8.js)。
- [rollup](https://rollupjs.org/configuration/)：`sourcemap: true`、`treeshake: false`。
- [esbuild](https://esbuild.github.io/api/)：`sourcemap: true`、`treeShaking: false`、`minify: false`。
- [vite](https://vitejs.dev/config/build-options.html)：`sourcemap: true`、`minify: false`。

请保留与实际测试构建对应的源码、生成文件和 sourcemap；详细说明参见 [Sourcemap 与调试](/zh/troubleshooting/sourcemaps)。

## 第二步：收集覆盖率 {#collect}

根据运行环境和接入方式，选择以下三种方案之一。

### 1. Node.js {#nodejs}

**通常不需要手动采集。** 使用 [`mcr`](/zh/reference/cli) 包装现有 Node.js 命令，或用 [`mcr test`](/zh/getting-started/node-test-runner#quick-start) 运行 `node:test` 测试。两者都会采集覆盖率并生成报告。

如果需要自行控制采集时机，或将采集接入自己的工具，可使用以下六种方案：

1. **进程退出时写入：[`NODE_V8_COVERAGE`](https://nodejs.org/docs/latest/api/cli.html#node_v8_coveragedir)。** 启动 Node.js 前将该环境变量设为专用目录。进程正常退出后，使用 `mcr.addFromDir(dir)` 读取其中的覆盖率 JSON。参见[采集示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-env.js)和[报告生成示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/generate-report.js)。
2. **进程内按需写入：[`v8.takeCoverage()`](https://nodejs.org/docs/latest/api/v8.html#v8takecoverage)。** 启动时同样设置 `NODE_V8_COVERAGE`。完成待统计的操作后，在被测进程内调用 `v8.takeCoverage()`，无需等待进程退出。每次写入后，执行计数会重置；如果需要整段运行的覆盖率，生成报告时应保留并导入所有快照。参见 [Node.js V8 API 示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-api.js)。
3. **进程内按区间采集：[Inspector](https://nodejs.org/docs/latest/api/inspector.html)。** 创建 `node:inspector` 会话，在测试前启用精确覆盖率，在测试后读取覆盖率条目。为条目附上实际执行的源码，再传给 `mcr.add()`。如果 `vm` 中执行的代码带有包装前缀，可用 `scriptOffset` 告诉 MCR 前缀的长度。参见[Inspector 示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-ins.js)和 [VM 示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-vm.js)。
4. **通过调试端口直接采集：[CDP](#cdp)。** 使用 [`--inspect`](https://nodejs.org/learn/getting-started/debugging) 启动被测进程，从另一个进程用 `CDPClient` 开始和停止 JavaScript 覆盖率采集。结果直接传给 `mcr.add()`，无需设置 `NODE_V8_COVERAGE`。参见 [Node.js CDP 示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-cdp.js)。
5. **为运行中的服务按需写入：CDP + `NODE_V8_COVERAGE`。** 如果服务不会自行退出，又不能直接在服务代码里调用 `v8.takeCoverage()`，可同时设置环境变量和调试端口。测试请求完成后，调用 [`CDPClient` 实例的 `writeCoverage()`](/zh/reference/types#coverageclient)，它会通过 CDP 让目标进程调用 `v8.takeCoverage()`。再用 `mcr.addFromDir(dir)` 导入快照，无需先停止服务。参见 [Koa 服务示例](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-koa.js)。
6. **从父进程收集子进程覆盖率：[`child_process`](https://nodejs.org/docs/latest/api/child_process.html) + `NODE_V8_COVERAGE`。** 启动 Node.js 子进程时传入覆盖率目录；如果子进程的工作目录不同，使用同一个绝对路径。等所有子进程正常退出并写完文件，再由父进程统一读取。若只需包装已有命令，直接使用 [MCR CLI](/zh/reference/cli#command-line)。

### 2. 浏览器 {#browser}

浏览器端的原生 V8 覆盖率采集仅支持基于 Chromium 的浏览器。通过浏览器自动化工具，在测试前开启采集，测试完成后获取 JavaScript 和 CSS 覆盖率数据：

#### Playwright {#playwright}

以下片段中的 `page` 是已创建的 [Playwright Chromium 页面](https://playwright.dev/docs/library#usage)。将 `your page url` 替换为被测页面地址，并在导航后执行测试操作、停止采集前等待操作完成。
```js
await Promise.all([
    page.coverage.startJSCoverage({
        // reportAnonymousScripts: true,
        resetOnNavigation: false
    }),
    page.coverage.startCSSCoverage({
        // Note, anonymous styles (without sourceURLs) are not supported, alternatively, you can use CDPClient
        resetOnNavigation: false
    })
]);

await page.goto('your page url');

const [jsCoverage, cssCoverage] = await Promise.all([
    page.coverage.stopJSCoverage(),
    page.coverage.stopCSSCoverage()
]);

const coverageData = [... jsCoverage, ... cssCoverage];

```
Playwright Test 自动 fixture 参见完整 [playwright-coverage 示例](https://github.com/cenfun/playwright-coverage)中的 [fixtures.js](https://github.com/cenfun/playwright-coverage/blob/main/fixtures.js)，接入方式见[最佳实践指南](https://github.com/cenfun/monocart-coverage-reports/blob/main/skills/monocart-coverage-reports/references/best-practices.md#complete-project-example)。
参见例子 [./test/test-v8.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-v8.js), [css](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-css.js)

更多集成示例参见 [Playwright](/zh/integrations/frameworks-and-tools#playwright)。

#### Puppeteer {#puppeteer}

> 取决于包管理器配置，Puppeteer 可能不会在安装依赖时下载浏览器。如果没有可用浏览器，请手动安装：
>
> ```sh
> npx puppeteer browsers install chrome
> ```

以下片段中的 `page` 是 Puppeteer 创建的页面，不是前面 Playwright 的页面对象；创建方式参见 [Puppeteer 示例](/zh/reference/cdp-client#puppeteer)中的浏览器与页面初始化部分。将 `your page url` 替换为被测页面地址，并在导航后、停止采集前执行和等待测试操作。

使用 Puppeteer 的覆盖率接口时，需要设置 `includeRawScriptCoverage: true` 获取原生 V8 脚本覆盖率，再与 CSS 覆盖率合并：

```js
await Promise.all([
    page.coverage.startJSCoverage({
        // reportAnonymousScripts: true,
        resetOnNavigation: false,
        // provide raw v8 coverage data
        includeRawScriptCoverage: true
    }),
    page.coverage.startCSSCoverage({
        resetOnNavigation: false
    })
]);

await page.goto('your page url');

const [jsCoverage, cssCoverage] = await Promise.all([
    page.coverage.stopJSCoverage(),
    page.coverage.stopCSSCoverage()
]);

// to raw V8 script coverage
const coverageData = [... jsCoverage.map((it) => {
    return {
        source: it.text,
        ... it.rawScriptCoverage
    };
}), ... cssCoverage];
```
参见: [./test/test-puppeteer.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-puppeteer.js)

更多集成示例参见 [Puppeteer](/zh/integrations/frameworks-and-tools#puppeteer)。

### 3. 通用 CDP 方案 {#cdp}

[Chrome DevTools Protocol（CDP）](https://chromedevtools.github.io/devtools-protocol/) 可用于连接开启调试端口的 Node.js 进程或 Chromium 浏览器。MCR 提供 `CDPClient`，可通过调试端口或已有的 CDP session 开启、停止采集并获取覆盖率数据。

接入方式和示例参见 [CDPClient](/zh/reference/cdp-client#cdpclient)。

## 第三步：生成报告 {#generate}

使用[快速开始中的 API 示例](/zh/getting-started/get-started#api)，按采集方式选择输入：

1. **采集接口返回的条目：** 将浏览器、Inspector 或 CDP 采集的 `coverageData` 传给 `mcr.add(coverageData)`。采集结束后关闭自己创建的浏览器或 [CDP 客户端](/zh/reference/cdp-client#generate)。
2. **Node.js 写入磁盘的快照：** 等覆盖率文件写完后，改用 `await mcr.addFromDir('./v8-coverage')`，路径应为实际的 `NODE_V8_COVERAGE` 目录，与报告输出目录分开。MCR 自己导出的 [raw 报告](/zh/reference/merging#manual-merging)则应通过 `inputDir` 导入。

**复制或合并 Node.js 覆盖率时：**

- **保留配套输入。** 保留被测源码和 sourcemap、原始 `coverage-*.json` 文件名，以及包含执行元数据的 `source-*.json` 捕获记录。
- **了解源码匹配。** 只有一份捕获时直接使用。同一 URL 有多份捕获时，优先选同进程、同线程且启动时间最接近但不晚于快照的记录。没有匹配时优先用不含元数据的旧记录，再按文件名顺序回退。[`dataDir`](/zh/reference/options#datadir) 也使用相同规则。
- **分开采集不同环境。** 不同构建、机器或 loader 请用独立采集目录。例如，一次运行捕获了原生 TS，另一次在同一 URL 执行转换后的 JS 却没有捕获源码，共用目录可能导致两次都误用原生 TS 的捕获记录。可分别导入目录，或使用 raw 报告。
