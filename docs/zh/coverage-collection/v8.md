# 采集 V8 覆盖率 {#v8-collection}

## 第一步：构建准备 {#build}

如果源码需要经过编译或打包，请先开启构建工具的 sourcemap 支持，以便将运行时代码的覆盖率映射回源码。建议关闭压缩和 tree shaking，便于排查覆盖率问题，并保留需要统计的代码。

- [webpack](https://webpack.js.org/configuration/)：`devtool: 'source-map'`、`mode: 'development'`，参见 [webpack.config-v8.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/build/webpack.config-v8.js)。
- [rollup](https://rollupjs.org/configuration/)：`sourcemap: true`、`treeshake: false`。
- [esbuild](https://esbuild.github.io/api/)：`sourcemap: true`、`treeShaking: false`、`minify: false`。
- [vite](https://vitejs.dev/config/build-options.html)：`sourcemap: true`、`minify: false`。

请保留与实际测试构建对应的源码、生成文件和 sourcemap；详细说明参见 [Sourcemap 与调试](/zh/troubleshooting/sourcemaps)。

## 第二步：收集覆盖率 {#collect}

根据运行环境和接入方式，选择以下三种方案之一。

### 1. 浏览器 {#browser}

浏览器端的原生 V8 覆盖率采集仅支持基于 Chromium 的浏览器。通过浏览器自动化工具，在测试前开启采集，测试完成后获取 JavaScript 和 CSS 覆盖率数据：

#### Playwright {#playwright}

以下片段中的 `page` 是已创建的 [Playwright Chromium 页面](https://playwright.dev/docs/library#usage)。将 `your page url` 替换为被测页面地址，并在导航后执行测试操作、停止采集前等待操作完成。
```js
await Promise.all([
    page.coverage.startJSCoverage({
        // reportAnonymousScripts: true,
        resetOnNavigation: false
    }),
    page.coverage.startCSSCoverage({
        // Note, anonymous styles (without sourceURLs) are not supported, alternatively, you can use CDPClient
        resetOnNavigation: false
    })
]);

await page.goto('your page url');

const [jsCoverage, cssCoverage] = await Promise.all([
    page.coverage.stopJSCoverage(),
    page.coverage.stopCSSCoverage()
]);

const coverageData = [... jsCoverage, ... cssCoverage];

```
Playwright Test 自动 fixture 参见完整 [playwright-coverage 示例](https://github.com/cenfun/playwright-coverage)中的 [fixtures.js](https://github.com/cenfun/playwright-coverage/blob/main/fixtures.js)，接入方式见[最佳实践指南](https://github.com/cenfun/monocart-coverage-reports/blob/main/skills/monocart-coverage-reports/references/best-practices.md#complete-project-example)。
参见例子 [./test/test-v8.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-v8.js), [css](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-css.js)

更多集成示例参见 [Playwright](/zh/integrations/frameworks-and-tools#playwright)。

#### Puppeteer {#puppeteer}

> 取决于包管理器配置，Puppeteer 可能不会在安装依赖时下载浏览器。如果没有可用浏览器，请手动安装：
>
> ```sh
> npx puppeteer browsers install chrome
> ```

以下片段中的 `page` 是 Puppeteer 创建的页面，不是前面 Playwright 的页面对象；创建方式参见 [Puppeteer 示例](/zh/reference/cdp-client#puppeteer)中的浏览器与页面初始化部分。将 `your page url` 替换为被测页面地址，并在导航后、停止采集前执行和等待测试操作。

使用 Puppeteer 的覆盖率接口时，需要设置 `includeRawScriptCoverage: true` 获取原生 V8 脚本覆盖率，再与 CSS 覆盖率合并：

```js
await Promise.all([
    page.coverage.startJSCoverage({
        // reportAnonymousScripts: true,
        resetOnNavigation: false,
        // provide raw v8 coverage data
        includeRawScriptCoverage: true
    }),
    page.coverage.startCSSCoverage({
        resetOnNavigation: false
    })
]);

await page.goto('your page url');

const [jsCoverage, cssCoverage] = await Promise.all([
    page.coverage.stopJSCoverage(),
    page.coverage.stopCSSCoverage()
]);

// to raw V8 script coverage
const coverageData = [... jsCoverage.map((it) => {
    return {
        source: it.text,
        ... it.rawScriptCoverage
    };
}), ... cssCoverage];
```
参见: [./test/test-puppeteer.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-puppeteer.js)

更多集成示例参见 [Puppeteer](/zh/integrations/frameworks-and-tools#puppeteer)。

### 2. Node.js {#nodejs}

::: tip 一般用户推荐使用 CLI
- [`mcr`](/zh/reference/cli#command-line)：为已有的 Node.js 脚本或测试命令采集覆盖率。
- [`mcr test`](/zh/getting-started/node-test-runner#quick-start)：使用 Node.js 内置测试运行器执行测试并采集覆盖率。

CLI 已封装 Node.js 原生覆盖率采集流程，可自动获取数据并生成报告，无需手动设置 `NODE_V8_COVERAGE` 或编写采集代码。
:::

以下是基于 Node.js 原生能力的底层方案，供需要自定义采集流程或开发集成工具的开发者参考；一般用户无需逐一配置：

- [NODE_V8_COVERAGE](https://nodejs.org/docs/latest/api/cli.html#node_v8_coveragedir)=`dir`
    - 使用Node.js环境变量`NODE_V8_COVERAGE`=`dir`来启动程序, 然后在进程正常结束之后，覆盖率数据将自动保存到指定的`dir`目录.
    - 从`dir`目录读取所有的JSON文件，来生成覆盖率报告
    - 参见例子:
    > cross-env NODE_V8_COVERAGE=`.temp/v8-coverage-env` node [./test/test-node-env.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-env.js) && node [./test/generate-report.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/generate-report.js)

- [V8](https://nodejs.org/docs/latest/api/v8.html#v8takecoverage) API + NODE_V8_COVERAGE
    - 如果进程不能正常结束，比如被强制关闭，或者压根就不结束，比如启动了一个服务类的，那么需要手动写入覆盖率数据，这里需要调用接口`v8.takeCoverage()`
    - 参见例子:
    > cross-env NODE_V8_COVERAGE=`.temp/v8-coverage-api` node [./test/test-node-api.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-api.js)

- [Inspector](https://nodejs.org/docs/latest/api/inspector.html) API
   - 首先连接到Node.js的V8 inspector
   - 然后使用inspector的覆盖相关API来开启和收集覆盖率数据
   - 参见例子:
   > node [./test/test-node-ins.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-ins.js)
   - vm的例子 (注意这里需要使用`scriptOffset`，因为vm里一般都会加一层包裹代码，需要这个偏移位置来修正覆盖率数据块的位置):
   > node [./test/test-node-vm.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-vm.js)

- [CDP](https://chromedevtools.github.io/devtools-protocol/) API
    - 开启[Node调试](https://nodejs.org/en/guides/debugging-getting-started/)
    - 使用CDP的覆盖率接口开启和收集覆盖率数据
    - 参见例子:
    > node --inspect=9229 [./test/test-node-cdp.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-cdp.js)

- [Node Debugging](https://nodejs.org/en/guides/debugging-getting-started) + CDP + NODE_V8_COVERAGE + V8 API
    - 如果启动了一个Node服务，可以手动调用`v8.takeCoverage()`接口来保存覆盖率数据，开启Node调试就可以远程通过CDP连接的`Runtime.evaluate`，来调用这个接口.
    - 参见[koa](https://github.com/koajs/koa)的例子:
    > node [./test/test-node-koa.js](https://github.com/cenfun/monocart-coverage-reports/blob/main/test/test-node-koa.js)

- [Child Process](https://nodejs.org/docs/latest/api/child_process.html) + NODE_V8_COVERAGE
    - 如果是子进程，可参见 [命令行](/zh/reference/cli#command-line)

### 3. 通用 CDP 方案 {#cdp}

[Chrome DevTools Protocol（CDP）](https://chromedevtools.github.io/devtools-protocol/) 可用于连接开启调试端口的 Node.js 进程或 Chromium 浏览器。MCR 提供 `CDPClient`，可通过调试端口或已有的 CDP session 开启、停止采集并获取覆盖率数据。

接入方式和示例参见 [CDPClient](/zh/reference/cdp-client#cdpclient)。

## 第三步：生成报告 {#generate}

将上面浏览器或 CDP 示例得到的 `coverageData` 传给[快速开始中的 API 示例](/zh/getting-started/get-started#api)，即可生成报告。示例中的输入、返回结果及其类型说明也统一见该处。

如果通过 `NODE_V8_COVERAGE` 将数据保存到了目录，则在被测进程退出后运行报告脚本，将 API 示例中的 `await mcr.add(coverageData)` **替换为**：

```js
await mcr.addFromDir('./v8-coverage');
```

这里的 `./v8-coverage` 必须是采集时 `NODE_V8_COVERAGE` 指定的目录。保留对应的被测源码和 sourcemap，不要将采集目录作为报告输出目录。它不同于用于[合并报告](/zh/reference/merging#manual-merging)的 MCR `raw` 报告目录（通过 `inputDir` 导入）。

采集结束后关闭自己创建的 browser；自定义 CDP 客户端的连接清理参见 [CDPClient](/zh/reference/cdp-client#generate)。
